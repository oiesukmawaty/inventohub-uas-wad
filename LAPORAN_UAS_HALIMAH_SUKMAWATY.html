2. PERANCANGAN SISTEM & BASIS DATA (CPMK 1 - BOBOT 15%)

Sistem InventoHub dirancang dengan arsitektur basis data relasional MySQL yang telah memenuhi kaidah normalisasi tingkat ketiga (3NF). Sistem mengelola 4 entitas tabel berelasi:

Nama Tabel Atribut Utama (Kolom) Relasi & Constraint Fungsi Bisnis
users id (PK), name, email (UK), password (Bcrypt), role 1-to-Many ke transactions Autentikasi & RBAC (Admin / Staff)
categories id (PK), code (UK), name, description 1-to-Many ke products Master kategori & taksonomi barang
products id (PK), category_id (FK), sku (UK), name, purchase_price, selling_price, stock, min_stock, unit FK ke categories.id (RESTRICT) Katalog master barang & ambang stok
transactions id (PK), user_id (FK), product_id (FK), type ('in','out'), quantity, reference_number, transaction_date FK ke users & products Audit log mutasi stok gudang
Alur Arsitektur Model-View-Controller (MVC):
Peramban Klien → [HTTP Request] → Route (web.php) → Middleware (Auth, CheckRole, CSRF) → Controller (Validasi Input) → Model (Eloquent ORM) → Basis Data MySQL → View (Blade + Tailwind) → [HTTP Response] → Peramban

3. IMPLEMENTASI BACKEND & OPERASI BASIS DATA (CPMK 2 & CPMK 3 - BOBOT 35%)

Aplikasi dibangun menggunakan Laravel Framework dan Eloquent ORM dengan fitur operasional lengkap:

  • Operasi CRUD Lengkap: Pengelolaan produk dan kategori master mendukung Create, Read, Update, Delete dengan validasi keunikan SKU dan kode kategori.
  • Pencarian & Filter Dinamis: Katalog produk memiliki fitur pencarian teks instan (berdasarkan nama dan SKU) serta filter dropdown per kategori.
  • Integritas Mutasi Stok (ACID Database Transactions): Transaksi barang masuk dan keluar dibungkus dalam DB::transaction() untuk menjamin atomisitas. Apabila terjadi kegagalan sistem di tengah proses, seluruh perubahan dibatalkan secara otomatis (Rollback).
  • Pencegahan Stok Negatif: Logika validasi server-side memastikan transaksi keluar (type = 'out') ditolak apabila jumlah permintaan melebihi kuantitas fisik stok yang tersedia.

4. KEAMANAN WEB & MANAJEMEN SESI (CPMK 4 - BOBOT 15%)

1. Proteksi CSRF

Seluruh form mutasi dan CRUD menyertakan token kriptografis acak @csrf yang diverifikasi secara wajib oleh middleware Laravel.

2. Mitigasi XSS (Cross-Site Scripting)

Sanitasi masukan menggunakan strip_tags() pada controller dan auto-escaping HTML entities melalui sintaks Blade {{ }}.

3. Pencegahan SQL Injection

Seluruh kueri basis data menggunakan PDO Prepared Statements & Parameter Binding bawaan Eloquent ORM.

4. Autentikasi & Session Defense

Enkripsi kata sandi menggunakan Bcrypt. Panggilan session()->regenerate() saat login mencegah serangan Session Fixation.

5. DEPLOYMENT & PUBLIKASI CLOUD (CPMK 5 - BOBOT 10%)

Aplikasi telah disiapkan untuk deployment cloud publik (Railway / Render / VPS) dengan lingkungan produksi terisolasi:

DB_CONNECTION=mysql • Document Root diarahkan ke direktori /public

6. JAWABAN ESAI KOMPREHENSIF (CPMK 1 S.D. CPMK 5 - BOBOT 25%)

Esai 1: Penjelasan Alur Data, Pattern MVC, dan Struktur Database

Pola arsitektur Model-View-Controller (MVC) bertindak sebagai pemisah tanggung jawab (Separation of Concerns). Aliran data dimulai saat pengguna mengirimkan HTTP Request (misal: penambahan produk). Router meneruskan request ke ProductController setelah lolos dari filter middleware. Controller mengeksekusi validasi server-side dan memanggil Product::create() pada Model. Model Eloquent mengonstruksi query SQL menggunakan parameter binding dan menyimpannya ke basis data MySQL. Integritas data dijaga melalui 4 tabel relasional ternormalisasi 3NF, di mana tabel categories dan products dihubungkan oleh Foreign Key dengan batasan ON DELETE RESTRICT agar kategori yang memiliki produk aktif tidak dapat dihapus sembarangan. Respon data kemudian dirender oleh template Blade dan disajikan ke antarmuka pengguna dalam bentuk HTML5 dinamis.

Esai 2: Penjelasan Logika Backend, Penanganan Error, dan Implementasi Sekuriti

Operasi bisnis pergudangan yang paling kritis adalah mutasi stok (barang masuk dan keluar). Untuk menjamin konsistensi data antara riwayat transaksi dan stok fisik, digunakan mekanisme transaksi basis data ACID melalui DB::transaction(). Jika proses pembaruan stok gagal, transaksi dibatalkan (rollback) secara otomatis sehingga tidak terjadi inkonsistensi saldo stok. Sistem juga memverifikasi bahwa pengeluaran barang tidak boleh melebihi sisa stok fisik. Pada aspek keamanan web, proteksi CSRF diterapkan pada seluruh form mutasi dengan token kriptografis, pencegahan XSS dilakukan dengan pembersihan tag HTML via strip_tags() dan auto-escaping Blade, serta mitigasi SQL Injection dijamin secara default oleh PDO Parameterized Queries milik Eloquent ORM.

Esai 3: Penjelasan Langkah Deployment, Konfigurasi Environment, dan Troubleshooting

Deployment aplikasi Laravel dilakukan ke platform cloud PaaS (Railway/Render) dengan menghubungkan repositori GitHub secara berkelanjutan (CI/CD). Basis data MySQL disediakan secara terpisah untuk menjamin persistensi data. Konfigurasi sensitif dipisahkan ke dalam variabel environment, di mana nilai APP_DEBUG disetel ke false di lingkungan produksi guna mencegah kebocoran informasi stack trace dan kredensial database kepada publik saat terjadi error. Web server dikonfigurasi agar Document Root hanya mengarah ke folder /public, menjaga keamanan file inti aplikasi. Apabila terjadi kendala teknis (troubleshooting), pemeriksaan dilakukan pada berkas log storage/logs/laravel.log, memastikan hak akses tulis pada folder storage, serta melakukan pembersihan cache konfigurasi menggunakan perintah artisan.
